# Application code

The application under `hc/`, `templates/` and `static/` is the original project's design; these are the invariants a change there has to keep.

- A check's stored `status` is authoritative for `down` alone: a check that is late and not yet processed still says `up` in the database — read `Check.get_status()` for the current status.
- An integration's outbound HTTP goes through `hc.lib.curl`, which enforces the private-IP block that `INTEGRATIONS_ALLOW_PRIVATE_IPS` controls, and no other module imports an HTTP client (set: the client imports in the non-test Python under `hc/`, as `c_http_clients_outside_hc_lib_curl` in `scripts/count-list.sh` lists and exempts them; a vendor SDK is outside it; count: `scripts/count-list.sh http-clients-outside-hc-lib-curl`).
- A dashboard or integration view loads a check, channel or project through the `_get_*_for_user` helpers in `hc/front/views.py` — the `_get_rw_*_for_user` ones where it writes — which enforce team membership and a member's write access, and takes an `AuthenticatedHttpRequest` (`hc/accounts/http.py`), whose `request.profile` `TeamAccessMiddleware` sets; an API view takes `authorize`, or `authorize_read` where a key without write access is enough, from `hc/api/decorators.py`, which set `request.project` and `request.readonly`, and `/api/v3/` is the one API version; `require_setting("NAME")` in `hc/front/decorators.py` answers 404 for a feature switched off; rate limits go through `TokenBucket.authorize_*`.
- `SITE_ROOT` may carry a path component, and `hc/urls.py` prefixes the routes with it: a URL is built with `reverse()` or `settings.SITE_ROOT`, not as a hardcoded absolute path.
- `hc/settings.py` reads the environment — `os.getenv` for strings, `envbool`, `envint` and `envsecret` for the rest, `envsecret` also from a `<NAME>_FILE` — and then imports the gitignored `hc/local_settings.py`, which overrides it except for SMTP: `hc/settings.py` always defines `MAILERS`, and Django 6.1 refuses `EMAIL_HOST` and the other deprecated email settings beside it, so SMTP set there goes through `MAILERS`; under a test run its tail sets a fast password hasher and `BLOCKING_EMAILS`, so mail is sent synchronously into `mail.outbox`.
- Code that touches queries, locking or transactions has to work on SQLite and PostgreSQL — CI runs both on the PR; locally `DB=postgres` with `DB_USER`, `DB_PASSWORD`, `DB_HOST` and `DB_NAME` selects PostgreSQL.
- `sendalerts` runs as several processes at once: `handle_going_down` and `process_one_flip` each claim their row with a conditional update only one process wins, and `Channel.notify()` disables the channel on a `TransportError` with `permanent=True`.
- A new integration copies a similar one under `hc/integrations/<kind>/` and follows "Developing a New Integration" in `CONTRIBUTING.md`, plus `INSTALLED_APPS` in `hc/settings.py`, which that checklist omits; `TRANSPORTS` in `hc/api/models.py` is the registry, `Transport` and `HttpTransport` (retrying over `hc.lib.curl`) in `hc/api/transports.py` are the bases, and `prometheus` is a metrics endpoint with no transport.
- Tests subclass `hc.test.BaseTestCase`: `alice` owns `self.project`, `bob` is a member of it, `charlie` has no access — the owner, member and outsider cases — with `set_sudo_flag()` for a view behind sudo mode and the `assertEmailContains*` helpers; a transport test mocks `hc.api.transports.curl.request` and asserts on the call, as `hc/integrations/slack/tests/test_notify.py` does.
- Nothing type-checks the code: new code is annotated like the code around it and a new module starts with `from __future__ import annotations`; `django-stubs-ext` is a runtime dependency, not type-checker residue — `hc/settings.py` calls its `monkeypatch()`, which the `ModelAdmin[Check]`-style admin bases need at import, and the code imports `WithAnnotations` from it.
- The user docs are `templates/docs/*.md`; the `.html-fragment` beside each and `search.db` are generated and committed. After an edit, `uv run ./manage.py render_docs`, then restore each fragment whose `.md` did not change (`git checkout -- <file>` — the pinned Pygments re-escapes quotes in them), and in a changed page's own fragment keep only the hunks of the changed text; where indexed prose changed, `PING_BODY_LIMIT=100000 uv run ./manage.py populate_searchdb` rebuilds the index at the limit the committed one was built with; a new page joins the navigation in `templates/front/docs_single.html`.
