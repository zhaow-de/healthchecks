# CLAUDE.md

## Orientation

Healthchecks is a cron job monitoring service: scheduled jobs ("checks") send "pings" over HTTP, and integrations send alerts when a ping does not arrive on time; a Django 6.1 application on Python 3.14, run through `manage.py` on SQLite (the default) or PostgreSQL.

- Package manager: **uv** (`pyproject.toml` + `uv.lock`); run all Python through uv — `uv sync`, `uv run ./manage.py runserver`, `uv run ./manage.py test [hc.api.tests.test_ping[.PingTestCase.test_it_works]]` for the Django suite, `uv run pytest -n auto` for the tooling tests (`uv run pytest tests/<file>::<test>` for one) and `uv run pytest hc -n auto` for the Django suite as CI's SQLite leg runs it, `uv run pre-commit run -a`, `uv add [--dev] '<pkg>==<version>'`. `pyproject.toml` and `uv.lock` are committed together: CI and the Docker build run `uv sync --locked`. Setup is README.md's "Setting Up for Development", then `uv run pre-commit install` once per clone: it installs the pre-commit and commit-msg hooks, and a clone without them commits unchecked.
- Layout: `hc/<app>/` — `accounts` (the one user, profiles, projects), `api` (the core models, the ping endpoints, the JSON API, the `sendalerts` / `sendreports` commands), `front` (the dashboard and the docs pages), `integrations/<kind>`, `lib`; the invariants of that code are `.claude/rules/hc-code.md`; `static/js/` has no build step; `scripts/` is the commit and review tooling, tested under `tests/`; `.local/agent-lessons/` is gitignored and KEPT (the lesson inbox), `.tmp/` is disposable (review reports and worktrees).
- Work branches are cut from `develop`, and every change reaches `develop` by a PR merged with a merge commit; GitHub refuses direct pushes to `develop` and `main` (`.github/settings.yml`) (set: `develop`'s first-parent commits since `PR_RULE_SINCE` in `scripts/count-list.sh`; count: `scripts/count-list.sh non-pr-commits-on-develop`). Commits follow Conventional Commits and are staged by explicit path rather than `git add -A`; type `claude`, with a scope (`claude(config)`, `claude(refine)`), for `CLAUDE.md`/`.claude/` changes (`.cz.toml`); the `staged-kind` hook refuses a commit that mixes those with other files. A breaking change is `!` after the type or scope, and a footer spells `BREAKING-CHANGE:` with the hyphen: the spaced form in the last paragraph stops git reading `Co-Authored-By:` there as a trailer.
- `main` is release-only and never rewritten: it moves by the `release` skill's merge of a `release/<timestamp>` branch, tagged `v<version>`, and takes no force-push and no history edit (no count command: nothing in this tree records a push to `main`; `allow_force_pushes: false` in `.github/settings.yml` refuses a forced one).

## Tooling

- Python is pinned to 3.14 in four places that change together — `.python-version`, `requires-python` in `pyproject.toml`, `default_language_version` in `.pre-commit-config.yaml`, the base image tags in `docker/Dockerfile` — and uv to one exact version in `docker/Dockerfile` and `.github/workflows/tests.yml`; PEP 758 makes `except ValueError, IndexError:` valid syntax and ruff writes it so — do not flag it or "fix" it in review.
- A new Markdown file is written with one line per paragraph and per list item — no column wrap, no filler blank lines; a fenced block keeps its own lines; an existing file is left as it is.
- The commit gate is `uv run pre-commit run -a` — file hygiene, `ruff check --fix` and `ruff format` (`ruff.toml`), shellcheck, ESLint over our JS (`eslint.config.js`, Node pinned in the hook), `staged-kind`; a run that rewrites files reports Failed and leaves the rewrites unstaged — re-run until clean, then stage what it rewrote; a file not yet `git add`ed is outside it. The installed commit-msg hook runs `scripts/message-citations.py` on the message; a refusal is fixed at its cause, and `--no-verify` or `SKIP=` is the user's call alone.
- A file committed exactly as a tool writes it — the `.html-fragment` files, `stuff/icons_icomoon_project.json`, `.idea/` — is excluded at the top of `.pre-commit-config.yaml`; a template that has to render to an empty string, as `templates/front/log_rows.html` does for `static/js/log.js`, takes the `end-of-file-fixer` exclusion there, and no test catches a missing one.
- CI is `.github/workflows/tests.yml`, on pull requests into `develop` and `main`: the Django suite on SQLite and PostgreSQL, coverage from the SQLite leg to Coveralls, and the tooling tests, aggregated as the check `Full test suite` that `.github/settings.yml` requires; a branch without a PR gets no run. `.github/workflows/image.yml` pushes `ghcr.io/zhaow-de/healthchecks` from `develop`, `main` and `v*` tags.

## GitHub

- This repository (`origin` is `zhaow-de/healthchecks`) was created from `healthchecks/healthchecks`, the original project, and is not a GitHub fork of it; that project accepts no AI-generated or AI-assisted contributions and has pull requests disabled, so never open anything there — no pull request, issue, comment or release (no count command: what `gh` creates in another repository leaves nothing in this tree).
- Every `gh` command names the repository — `--repo zhaow-de/healthchecks`, or a `gh api` path spelled `repos/zhaow-de/healthchecks/...`, reads included: `gh` otherwise picks its target from the clone's remotes and `gh repo set-default`; after a create, the URL `gh` prints starts with `https://github.com/zhaow-de/healthchecks/`, or stop and tell the user (set: the `gh` invocations in the tracked files under `.claude/` and `scripts/`, Markdown read as code alone, `gh auth` exempt; count: `scripts/count-list.sh gh-calls-without-the-repo`).

## Guards and proofs

- A comment or docstring earns its place when a reader would do something differently without it, and what stays has to be correct — state and decisions stay, an event (what was measured, read, found or corrected) goes to the commit message; the `pre-review` workflow grades a range on this.
- A lesson — *it was mine*, *I mistakenly*, *the third time*, *a miscount* — goes through `scripts/append-lesson.py --session main` into `.local/agent-lessons/main.jsonl` the moment it happens; the refine round reads the inbox.

## Releases and PRs

- The version is written by `cz bump`, which the `release` skill runs, into `.cz.toml` and `pyproject.toml`, and `uv lock` carries it into `uv.lock`: a hand edit leaves the three apart (set: those three homes; count: `scripts/count-list.sh version-homes-that-disagree`).
- There is no `CHANGELOG.md`, and none is created: release notes are written into the GitHub Release (set: the tracked files named `CHANGELOG.md` in any case and directory; count: `scripts/count-list.sh changelog-files`).
- PRs target `develop` and are opened on the user's word — a finished branch is not a reason by itself; before the push a PR carries, agents other than its author read the whole branch — the `pre-review` workflow over a range's prose and message claims before each read of it, `review` once the branch is complete, `re-review` over a fix range at most twice, a Critical or Important still open after the second going to the user — and the PR body names who read it and the tip they read, the line `open-pr` writes and `merge-pr`'s gate (`scripts/merge-gate.py`) checks; create or edit through the `open-pr` skill, merge through `merge-pr`, release through `release`.
